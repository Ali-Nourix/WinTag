# WinTag Preview 0.2.0 — پیش‌نمایش قابل اجرا، نه نسخهٔ کامل v1

## اجرا

ویندوز ۱۱ x64 و .NET 10 Windows Desktop Runtime x64 لازم است. گزارش قبلی شما نصب این
runtime را نشان می‌داد. کل ZIP را در پوشهٔ محلی تازه استخراج و **WinTag.Preview.exe** را
معمولی، بدون Administrator اجرا کنید. این بسته installer، دانلود خودکار یا telemetry ندارد.
اگر Windows امنیت فایل را تأیید نمی‌کند، تنظیمات امنیتی را غیرفعال نکنید؛ سورس قابل ساخت است.

- پنل ابتدا باز می‌شود؛ سپس از آیکن کنار ساعت، Ctrl+Alt+Space یا وسط لبهٔ راست مانیتور بازش کنید.
- با عنوان فارسی/انگلیسی یا نام تگ جست‌وجو کنید. Enter/دوبارکلیک پنجره را فعال می‌کند.
- ردیف را انتخاب کنید؛ F2 یا «تگ‌ها» برای ویرایش چند تگ. تگ اول اصلی است.
- کلیک راست: بازگشت به قوانین خودکار، کوچک‌کردن/بستن عادی پنجره یا اعضای تگ اصلی.
  بستن گروه تأیید می‌خواهد؛ هیچ فرایندی force-kill نمی‌شود و درخواست ذخیرهٔ خود برنامه حفظ می‌شود.
- آیکن کنار ساعت → «نشانگر بسیار کوچک عنوان»: نشانگر اختیاری و آزمایشی ۸۸×۱۸ DIP، متن کوتاه
  و لبهٔ رنگی باریک. پیش‌فرض خاموش است و فقط برای پنجرهٔ فعال نمایش داده می‌شود. اگر روی تب یا
  کنترل برنامه قرار گرفت خاموشش کنید. این نشانگر پنجرهٔ خود WinTag است؛ DWM یا استایل برنامهٔ
  دیگر را تغییر نمی‌دهد. ظاهر و عبور واقعی کلیک هنوز باید روی ویندوز بررسی شوند.
- توقف: hotkeyها و بازشدن از لبه غیرفعال و نشانگر پنهان می‌شود؛ آیکن کنار ساعت باقی می‌ماند.
- خروج: آیکن کنار ساعت → خروج. هیچ رنگ اصلی یا عنوانی در برنامه‌های دیگر تغییر داده نشده است.

## شورت‌کات و تنظیمات

«تنظیمات / شورت‌کات» ویرایشگر JSON داخلی است؛ tag، رنگ، قانون، ignore و کلیدها قابل تغییرند.
مسیر جداگانهٔ پیش‌نمایش: `%AppData%\WinTag\Preview\config.json`؛ قرارداد نسخهٔ نهایی را
جایگزین یا migrate نمی‌کند. فایل خوانا، محلی و دارای backup هنگام ذخیره است. ورود JSON
ابتدا به ویرایشگر می‌آید و فقط با «ذخیره و اعمال» جایگزین می‌شود. برخورد کلید یا ذخیرهٔ ناموفق،
کلیدهای قبلی را حفظ می‌کند. «خواندن فایل محلی» برای بارگذاری ویرایش بیرونی است؛ polling نداریم.

- `Modifiers`: Alt=1، Ctrl=2، Shift=4؛ جمع کنید. Win مجاز نیست.
- `Key`: کد مجازی ده‌دهی؛ Space=32، 1=49، 2=50 و تا 9=57.
- `Action: Picker`: پنل جست‌وجو؛ پیش‌فرض Ctrl+Alt+Space (این نسخه tag-picker کامل نیست).
- `Action: Preserve`: حالت B، بدون جابه‌جایی دسکتاپ؛ پیش‌فرض کار Ctrl+Alt+Shift+1 و شخصی
  Ctrl+Alt+Shift+2. پنجره‌های محلی restore/فعال می‌شوند، پنجره‌های remote جابه‌جا نمی‌شوند.
  ویندوز ممکن است بعضی درخواست‌های فوکوس را رد کند؛ در پنل گزارش می‌شود.
- `Action: Gather`: حالت A **غیرفعال**؛ اگر تعریف شود، پیام عدم پشتیبانی می‌دهد و به B تبدیل نمی‌شود.
- برای افزودن تگ/کلیدهای بیشتر JSON را ویرایش کنید؛ `TagId` باید با `Id` تگ یکی باشد.
- `Rules`: Process نام بدون exe؛ WindowClass تطابق دقیق؛ Title زیررشته یا Regex؛ شروط AND؛
  Priority کمتر جلوتر، سپس ترتیب فهرست. Regex حداکثر ۵۰ms برای هر تطابق؛ تا ۶۴ قانون.
- انتخاب دستی حتی فهرست خالی با اجرای دوبارهٔ قواعد تغییر نمی‌کند. **فقط همین اجرا** حفظ می‌شود؛
  پس از خروج یا بسته‌شدن پنجره فراموش می‌شود. بازیابی امن override بعد از restart هنوز پیاده نشده است.

## عمداً هنوز فعال نیست

انتقال/ساخت/تعویض دسکتاپ و Gather A، ذخیره/بازیابی layout، autostart، تنظیمات کامل دو‌زبانه،
tag-picker دوحالته و بازیابی override پس از restart در این پیش‌نمایش آماده نیستند. نسخهٔ حاضر
نشانگر عنوان را experimental و opt-in نگه می‌دارد و هیچ DWM خارجی یا COM مستندنشدۀ دسکتاپ
فراخوانی نمی‌کند. پنجره‌های cloaked توسط shell ممکن است فقط به‌عنوان remote نمایان شوند؛
تشخیص دقیق دسکتاپ و پوشش تمام برنامه‌های WinUI/UWP هنوز گواهی نشده است.

WinEventHook قبل از EnumWindows نصب می‌شود؛ فهرست با کلید HWND و generation نگهداری می‌شود،
نه افزودن رکورد Snap Group. این معماری به‌تنهایی اثبات پوشش کامل یا exactly-once روی همهٔ shellها
نیست. ناحیهٔ لبه: ۶ DIP، ۳۰٪ میانی؛ لبهٔ مشترک ۲۵۰ms؛ fullscreen مانیتور suppress می‌شود؛
scroll رویداد بازکننده نیست. تنها تایمر dwell یک‌باره است، نه refresh دوره‌ای.

این preview روی Linux cross-build شده؛ تست بومی اجرا نشده. ۲۴ تست مدل/تنظیمات پاس شده‌اند؛
مصرف <۱۰۰MB، تأخیر <۱۰۰ms، قابلیت DPI/چندمانیتور و ایمنی واقعی ورودی هنوز تأیید نشده‌اند.
نسخه‌های قبلی Spike snapshot حافظهٔ بالاتر از هدف داشتند؛ این preview ادعای حل مصرف حافظه ندارد.

## ابزار تشخیصی اختیاری

پوشهٔ `diagnostics` ابزار Spike 0.1.3 اصلاح‌شده است، نه برنامهٔ اصلی. اجرای آن لازم نیست برای
استفاده از preview. خطای قبلی از ساخت writer با AutoFlush قبل از اتصال pipe بود؛ اکنون ابتدا
اتصال برقرار می‌شود. بازتولید pipe واقعی و ۵۱ تست قابل‌حمل پاس شده‌اند؛ DWM روی ویندوز هنوز
تأیید نهایی نشده است. این ابزار فقط پنجرهٔ آزمایشی خودش را رنگ می‌کند.

## ساخت

```powershell
dotnet restore previews/WinTag.Preview --locked-mode
dotnet publish previews/WinTag.Preview -c Release -r win-x64 --self-contained false
dotnet run --project previews/WinTag.Preview.Tests -c Release
```

.NET SDK 10.0.403، CsWin32 0.3.367 pinned. از WinForms فقط NotifyIcon/Screen و از WPF برای
UI استفاده می‌شود؛ WPF/manifest مالک DPI است و suppress دقیق WFO0003 به همین دلیل است.
